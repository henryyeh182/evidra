Before The Chain

證據怎麼到 AI 手上

實際情境是這樣開始的：使用者在手機上打開 Claude，說「今天該練什麼」。 決策鏈要能開始，證據得先進到那句對話裡；決策做完之後，還得走回去變成一句人話。 這是一趟往返，而這趟路上不是每一步都由我們走—— 誰負責哪一步，決定了這個產品什麼時候能上手機。

授權對象自始至終是使用者已經在用的那個 AI，不是我們。 這不是權宜之計——它是「不建資料湖」這條原則的執行方式： 我們沒有拿到金鑰，就沒有能力保存任何人的健康資料， 不需要靠承諾來保證，架構上就做不到。

往返鏈的兩端都已經存在——手機上的對話、把結果講成人話，都是 host 本來就會做的事。 紅的是中間那三步（連上 Evidra、Apple Health、Garmin ／ Strava），而且只有第一步是我們做得完的。 OAuth 做好，Apple Health 與 Garmin 的取用也不會自動出現—— 手機情境能不能成立，有一半取決於 host 支援到哪裡。 這一段之所以要寫進來，是為了不讓「等 OAuth 做完就好了」變成一句誤導人的話。

The Chain

五層決策模型

每一層都有明確產出，且不可跳層。以下走完一次真實的判定—— 一位半馬訓練者，昨天跑了 80 分鐘 RPE 8，今天排定 VO₂max 間歇。

Evidence

證據由 AI Agent 帶進來，我們不去拿

授權對象是使用者已經在用的 AI，不是我們。證據經 tool call 以參數傳入—— Evidra 不連廠商雲端，只處理呼叫端送進來的最小化證據，算完不留。 所以「Apple Health 沒有伺服器 API」這類問題，在這個架構下不存在。

精確講不是「完全不碰健康資料」——收到證據、算出決策，這中間就是在處理它。 對外承諾的正式表述是： “We process only the minimum health-related evidence submitted by the caller, solely to compute the requested fitness decision. We do not retain, sell, use for training, or use it for unrelated purposes.”

Decision → Action

意圖與變更分開：一個判斷，可對應不同做法

Decision 是意圖（降低今天強度）；Action 是具體變更（from → to）。 分開的理由：同一個意圖，在不同器材、時間、傷病下會落成不同的 Action。

決策型別有五種：keep（照原定執行，也是決策）· adjust · substitute · defer · advance。 規則各自提出降幅、取最大值，所以順序不影響結果，每條觸發的規則都留下理由。

Escalation

隔天，同一條鏈，不同的決策

決策型別不是固定的——它跟著證據走。同一位使用者隔天再問一次： 昨天那場 95 分鐘 RPE 9 之後，HRV 掉到 33（個人基線 48）、Body Battery 只剩 24。 這次引擎不是調降強度，而是把整堂課換掉。

換課就要連動作一起換。 若只改標題而留著原本的 Tempo Run， 這份紀錄會自相矛盾——使用者看到「恢復課表」卻配著「節奏跑」。 換上的是徒手、低衝擊的動作，因為 readiness 低的日子往往伴隨關節限制。

五種決策型別都是決策，包含 keep——照原定執行同樣要附上證據， 不是「沒事發生」而是「檢查過了，可以執行」。

沒有人需要湊齊來源

每一組來源都能產出決策，差別在用什麼證據做，不在夠不夠格。 系統對缺漏的處理是把權重在有效訊號之間重新正規化，並如實回報信心—— 不是等湊齊了才開始工作。

使用者手上有的決策依據能做出的決策
只有 Strava 訓練負荷 ATL / CTL / TSB 依負荷曲線調整強度與量
只有 Apple Watch HRV · 靜息心率 · 活動 依恢復訊號與肌群疲勞調整

多接一家不會讓決策從「做不到」變成「做得到」，只會讓同一個決策的信心提高。 這也是為什麼產品的價值不以 connector 數量衡量。

Guarantee

寫入前必須先看見

改動計畫走兩階段：preview 回傳 diff 與 token， 沒有有效 token 的 commit 一律拒絕； preview 之後計畫若已變動，commit 會因版本不符而失敗，而不是覆蓋掉別的改動。

preview_adjust_plan→ previewId · diff · baseVersion
commit_adjust_plan→ 驗證 token 與版本 → v2
若版本已變拒絕：Preview is stale

模型可以被說服、被繞過；確定性的檢查不會。 傷病禁忌也是同一類保證——它是硬過濾，不是給模型參考的建議。

這條鏈為什麼難被取代

證據

GPT-6 沒有這個人的 HRV、睡眠、42 天訓練史。除非經過授權層，它永遠拿不到。

計算

它知道 CTL 的公式，但沒有資料、也沒有執行那條 42 天的縱向運算。

保證

模型可以被說服繞過安全規則；確定性過濾器不會。傷病硬過濾與兩階段寫入都屬此類。
